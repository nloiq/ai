## Media review

Upload a static PNG, JPEG or WebP and provide English/Arabic alternative text. The form accepts up to 8 MiB; the decoder also checks the detected format, extension/MIME agreement, frame count, 8,000-pixel side limits and 16-megapixel ceiling before allocating decoded pixels. Unsupported or corrupt files are rejected. SVG, GIF, ICO, scripts and documents are not upload formats.

Images are oriented from EXIF before resizing and freshly encoded without the original metadata/trailing payload. The master fits within 2,400 pixels on its longest edge, without upscaling. Generated files are WebP master/thumbnail and 640/1280-wide variants where applicable, plus a transparent 64 × 64 PNG browser icon. Transparent backgrounds are preserved. Two concurrent decoder slots bound processing pressure; deployment capacity tuning remains release work.

The authenticated library shows thumbnails, dimensions, optimized bytes, references and alt hints. Select an uploaded asset in a content draft; its library hints are copied as suggestions. The content revision owns its actual alt/caption snapshot. Updating library hints does not change an already published page. Stale hint forms are rejected with a row lock plus a current-value version check.

Files are stored under ignored `src/NLOIQ.Web/App_Data/media`, outside `wwwroot`, using generated keys. Original filenames are display text only. Public `/media/{id}/{size}` delivery requires a non-demo asset referenced by a currently published revision or an eligible pinned section. A draft attached to an already published content root does not expose its new media. Authenticated previews are separate and no-store.

SuperAdmin can delete unused uploads. Any revision reference, including archived/history snapshots, prevents deletion. Replacing an image requires a new upload and a new content revision; used bytes/metadata are never overwritten. Successful deletion removes its database row and generated local folder. A filesystem cleanup failure is logged and leaves an inaccessible orphan for maintenance; an ambiguous upload commit preserves files conservatively. There is no automatic historical-media garbage collection in this phase.

The retained `phase8-media-review.png` is an actual uploaded technical workflow illustration, attached to the bilingual CMS review page. It is a review fixture, not a completed client project or the company's official logo. Its original raster is reproducibly generated by the browser test; runtime uploaded bytes are not committed to Git.

## SEO review

Open the SEO manager and edit a page/project. Each translation includes search title/description, sharing title/description, image role, local canonical path and noindex. Blank overrides fall back to content text. Sharing images refer to media in the same revision; removing a selected image clears a stale sharing reference safely.

Save a draft and inspect the public page: its existing metadata remains. Publish explicitly to apply the new metadata. Public HTML includes title, description, robots, canonical, language alternatives and Open Graph fields. Canonical overrides must be local paths without query/fragment or scheme-relative destinations. The verified HTTPS origin in Site settings makes canonical/sharing URLs absolute; no domain is invented when that setting is blank.

The live demonstration is http://127.0.0.1:5080/en/pages/cms-review and http://127.0.0.1:5080/ar/pages/cms-review. Its published search titles are **NLO IQ | Media and SEO review** and the corresponding Arabic title. Sharing image selection points to its uploaded illustration. Development always emits noindex in HTML and response headers, regardless of the saved flag. Production indexing/domain decisions remain deployment work.

## Site and appearance review

Site settings manage the site name, default language, default theme, verified HTTPS origin, logo, generated browser icon and social links. A stored visitor theme preference takes precedence over the configured default. The root redirect uses the published default language. Logo selection includes revision-owned bilingual alt text. Social links require approved platforms and safe HTTPS destinations.

Appearance exposes only predefined brand color tokens: evergreen, forest, moss, burnt orange, copper, gold, ivory, charcoal and readable action/signal accents. Six-digit color validation and text/surface contrast checks run before saving. Light/dark sample panels preview draft values locally. Only publishing creates a public `/brand/{revision}.css` link for public/admin pages; draft CSS is unavailable. No arbitrary CSS or JavaScript is accepted.

The browser test proved default-language/theme, logo/icon, absolute canonical and palette persistence, then restored **NLO IQ**, English/system defaults, no invented public origin, no test logo/favicon and the approved default colors. Site/theme roots now publish truthful default-setting descriptions; actual branding files and social URLs remain for the user to supply. The review illustration remains selected only on the review page, not as the company logo.

## Audit history

Audit history is read-only and append-only. It shows UTC time, actor, action, content/revision references and encoded details, with content filtering and paging. Media uploads, alt suggestion changes and unused deletion have dedicated audit actions. Content/settings draft saves and publication reuse their existing transactional audit records. Logs do not contain passwords or original uploaded image metadata.

## Dependency and deployment notes

Image processing uses pinned [SkiaSharp 4.153.1](https://www.nuget.org/packages/SkiaSharp/4.153.1), with matching [Linux native assets](https://www.nuget.org/packages/SkiaSharp.NativeAssets.Linux.NoDependencies/4.153.1). Windows decoding is verified here; target Linux/runtime verification remains deployment QA. Keep the package/native security audit current.

Uploads and local configuration are excluded from Git and application publish content. Preserve/back up `App_Data/media` alongside the database; a code checkout alone does not recreate user uploads or the current database. Production storage permissions, backup/restore, shared Data Protection keys, TLS/proxy settings and host resource limits remain Phase 12 work. A crash can leave unreferenced files, so deployment maintenance needs a conservative orphan audit rather than deleting history blindly.

Phase 9 completes localization. Phase 10 adds scheduling, preview links and revision restoration. Full release QA/deployment remain Phases 11–12. No production-readiness claim is made.
